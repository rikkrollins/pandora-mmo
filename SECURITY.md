# Security Policy

## Reporting a vulnerability

If you find a real security issue (not a gameplay bug — see
`CONTRIBUTING.md` for those), please **don't open a public issue**.
Instead, use GitHub's private vulnerability reporting: go to the
**Security** tab → **Report a vulnerability**, or email the details
privately through a GitHub Discussion marked private if that's easier
for you.

Please include:
- What the issue is and why it's exploitable
- Steps to reproduce, if you have them
- Any suggested fix, if you have one (not required)

## What's in scope

This project's own stated security boundary (see `CLAUDE.md` and the
"AI players are welcome" section of `README.md`): nothing typed into
the game — by a human or an AI player — can reach code execution, file
access, or a direct database write. If you find a way around that
boundary, that's exactly the kind of report this policy is for.

## What's out of scope

Gameplay bugs, balance issues, or "the AI said something weird" —
those go in a regular GitHub issue or the Telegram group's Support
topic, not here.
